# GR III / GR IIIx 上传版本兼容修复

基线：`8bc3dee4b412d224a122026a985cd2c63658be35`（2026-10-28 fetch 后与 origin/main 相同）。分支：`daily/gr3-firmware-version-compat`。用户在交付候选后明确授权合并 main、发布 GitHub 和宝塔；该发布授权不作为实机刷入或恢复通过的证据。发布版本为 2026.10.28.5，实际部署结果以对应 GitHub Actions 与线上核验为准。

## 问题与实现

原网页导入要求固定文件长度和完整 SHA-256；此前仅单独加入 GR III 2.20。用户提供的 GR IIIx 1.70（30472528 bytes）仍无法上传。更新兼容处理也只对 GR III 2.20 的固定 SHA 生效。

- 上传、机型识别、项目重读、备份创建及还原改用独立的结构检查：根据容器声明长度解码，检查机型/标记、帧边界、分区顺序/类型/边界、外层及解码 checksum、CPU 项目与 BE checksum、四份版本一致性。保留 128 MiB 上限，拒绝非法输入和越界分配。
- 未登记版本不依赖长度或 SHA 白名单。SHA 作为原包和备份身份保留；未登记来源报告 `proof.identity:false`，界面显示“固件结构核验通过”，不将 checksum 当成官方真实性证明。
- 沿用现有构建基线策略：GR III 采用已适配 2.10，IIIx 采用已适配 1.60。未知上传代码不参与补丁构建；底层 `inspectOfficial`、本地基线完整 SHA、preimage、model-word overlap 和最终候选差分审计保持严格。
- 对归一化后的上传版本，逐机型从四段内部版本计算高于输入/基线的包版本，修正 DSP/CPU 的内外版本和 CPU/容器校验，沿用已有 recoverable updater 补丁，并独立回读。版本字段溢出明确拒绝。原版 2.10/1.60 导出不增加此步骤。
- 保留现有胶卷目录、槽位、ISP 管线、存档、网页配置与各机型功能。此改动不是将新版原厂功能移植到 M10V。

已考虑直接去掉所有校验与直接对新版地址打补丁；两者都无法保证指令和 ABI 正确，因此使用独立上传解析器及原有已适配构建流程。

未来固件如更换容器或组件格式，需要适配解析器，不能承诺任意格式均可刷写。输出包版本高于上传版本不证明高于用户机内未知服务版本，也不证明厂商更新器一定接受。尚未执行相机刷入、恢复、菜单、拍摄、连拍或重启验证，未修改或写入相机/SD。

实测需分别核对各机型 BIN 哈希，确认更新可识别并完成，检查冷启动、原厂菜单、胶卷切换、首张/连续至少三张、RAW+JPEG 与回放、重启保存；失败时回传更新提示及对应 build_id 的 M10VMN0/1.BIN、M10VCP0/1.BIN 等日志。恢复时仅使用本机型原厂包，当前测试包内的恢复准入补丁尚未得到实机验证，不保证无法启动设备的恢复。
