# r13：适配原厂工作区的数据区与对齐契约

仅支持 GR III 2.10 / GR IIIx 1.60，沿已测试的 r12 基线修正，不推送、合并或部署。

## 本轮真机证据

六份日志 CRC 全部有效，同一 build_id=f067019e，匹配 GR III r12；无冲突页。
本张漏光3、模糊0、颗粒关闭，6000×4000，设置序号24。
r12 的格式字段修正已使本张建立计划：planned=1、workspace_bytes=48000000。
原厂工作区查询返回成功，stock_query_valid=1；第二次设置后原厂执行返回1。

所以本轮明确停在新效果执行前的工作区校验，尚不能诊断成文件损坏或相册解码故障。

r12 没记录原分配地址/容量，也没细分工作区拒绝原因；其 FXH12 的detail=1只是原厂返回值，
不能据此断言具体地址、对齐或哪一个重叠检查失败。

## 两项原厂契约修正

1. 原厂启动页表53004000对两个数据区作身份映射：55000000..80000000、
   a0000000..e0000000（末端不含）。两个机型的全部相关section均有相同14c26属性和client domain。
   旧实现错误复用了只允许低地址的元数据检查，拒绝上部数据区的工作缓冲。
   新的buffer span检查只用于照片/工作平面；recipe、SI、参数、服务/控制器等元数据仍按原界限和归属验证。
   80000000..a0000000的空洞、e0000000及跨界span仍拒绝，不作所谓缓存别名转换。
2. 原厂查询53503398..39c在非零结果上加16字节，原厂Granulation也在5367ad8c..adac显式对齐。
   新效果不能要求原分配指针天然16字节对齐。r13在原分配内部建立16字节对齐视图，
   从可用容量扣除前移字节，再验证有效容量和完整原分配与各受保护对象/照片平面的重叠。
   不改写原参数中的指针/容量，不增加整图分配，最终仍由原厂释放原始分配指针。
   单开模糊无需新增纹理工作区，保留原厂已完成阶段的工作区契约。

这是对有原厂代码支持的合法输入布局进行适配；本轮相机到底触发哪一项限制，仍需新增原分配记录核验。
不移除完成、容量、重叠或安全释放检查，不改动ISP等待/回调，不制造完成mask，无CPU像素处理或CPU噪声生成。

## r13日志字段

FXW0 / 46585730：原厂分配地址、原始容量。
FXW1 / 46585731：通过校验后的私有对齐视图、扣除偏移后的容量；失败时两值为0。
只有含这些新记录的r13中，FXH12的detail才是以下细分原因：

- 1：原厂context不符合边界；2：原始容量不足；3：地址/数据区span不合法。
- 4：对齐后容量不足；5..10：与recipe/参数/values/源描述符/目标描述符/context重叠。
- 11：与SI重叠；12..15：与源Y/源C/目标Y/目标C平面重叠。

诊断只记录元数据，不控制成像或释放；不在等待循环、IRQ或任务生产者中写卡。
