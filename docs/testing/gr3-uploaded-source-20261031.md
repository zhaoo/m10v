# GR III / IIIx 上传固件来源修正：部分实现，原生新版移植未完成

基线为 `b0c6c9053dcfa65c8d4e670030db75d714673dab`，与本轮 fetch 的 origin/main 相同；既有部署 Actions `41181403067` 的 `DEPLOY_OK` 日志也确认该 SHA、`service=active`。本地分支 `daily/uploaded-firmware-source`。用户在明确获知本轮仅完成部分修复后，直接要求合并 GitHub main 并发布 GitHub 与宝塔，因此按该指令发布来源修正及兼容门禁，发布编号 `2026.10.31.5`。此授权不作为设备验收证据，实际合并和部署结果以本轮发布记录为准。本文不代表原始适配目标已全部完成，也不是可刷测试包交付。

## 根因

`resolveBuildSource()` 无论上传什么版本，都会读取本地 GR III 2.10 / IIIx 1.60。后续服务器导出再按上传版本提高旧包的四处版本字段。这样上传原包只是备份和版本信息来源，实际执行内容来自旧包。仅修改显示版本无法满足“基于上传固件进行改动”。

两份真实输入分别为 GR III 2.20.20.28、IIIx 1.70.20.18。新版 RTOS 长度由 17,520,064 增至 17,520,384；初始化数据源移动 0x100，长度增加 0x40；语言指针目录移动 8 字节；末尾 JPEG 描述符从 13 项变成 15 项。ICONBIN 图标仍为 671 项。SRIC、CPU、SHELLCMD、RES 也有差异。

多个原生代码区域以不同幅度移动，不能给所有地址加同一常数。对照 GRKit 掩码窗口和引用证据的只读调查中，发现仅按内容匹配的启动数据源候选与实际启动字面量冲突，因此未采用批量地址替换，也未输出未经核验的新原生候选。

## 已改动

- 构建来源保留实际上传字节，报告中的输入和输出来源身份相同。服务器取消自动提高包版本及修改更新器的后处理。
- 原厂预设改名、图标编辑直接在本机型上传包上执行，IIIx 的纯数据编辑不再经 GR III 参考包移植。封包独立回读检查组件版本、checksum、非目标字节及实际名称/像素。
- 资源地址从输入启动复制信息推导；语言目录通过结构、十二个原厂英文名称及唯一性定位；目录内的 ICONBIN 图标与外部 JPEG 描述符分开验证。没有添加 2.20/1.70 的固定地址分支。
- 原生胶卷预检改为核对已审阅目标的容器头和全部分区依赖。仅忽略两处外层版本、RTOS 版本四字节、CPU 版本四字节及对应 CPU checksum。版本数字本身不作为 ABI 放行依据；未知代码、布局和资源差异明确拒绝，不替换旧固件。
- 未登记但执行依赖完全相同的版本标识变更，可使用实际上传包走默认原生构建。GR III 的旧 GRLife 画幅/水平仪扩展仍依赖完整身份，预检明确拒绝该组合，避免先报 ready 再构建失败。

## 保留与未完成

保留旧目标的补丁前像、全模块和封包审计、机型隔离、胶卷数据与状态存储。原包备份、SD 准备及显式旧版桥接机制未改为新版本实现。

**尚未完成用户要求的 GR III 2.20 / IIIx 1.70 完整原生胶卷固件移植。** 当前这两个真实版本的原生预检会返回 `M10V_NATIVE_ABI_NOT_PORTED`。这是消除旧包替换后暴露的真实兼容边界，不是完整修复结果；本次部分实现的站点发布不得被描述为新版全功能 BIN 交付或实机刷入问题已解决。

下一阶段需要建立有类型的固件地址/对象依赖清单，为新目标逐项核对函数、数据、调用点、快照与生成代码的引用闭包，再接入目标化编译和补丁审计。仅通过地址搜索、checksum 或版本比较均不足以放行。后续新版本只有在对应执行与资源依赖得到证明时才能构建，不承诺未知 ABI 自动兼容。

## 验证

先新增真实来源断言，观察两份上传都被替换成旧包；再新增新版资源读取、原生预检和图标编辑断言，分别观察旧绝对地址、错误 ready 和外部 JPEG 被误当 RGBA 的失败，再实现修正。

- 两份真实输入的来源保留、资源读取、改名与图标编辑、非目标组件保持、四处版本回读及 HTTP 导出专项通过；没有跳过真实输入。
- 构造的版本标识变更 2.30.3.4 / 1.80.3.4 已实际完成默认原生编译与封包回读，输出保留该输入内部版本。它们是合成兼容性用例，不是未来官方固件适配或相机验收。
- IIIx 移植的固定差异统计不再计入版本字；新增验证允许上传版本与 GR III 参考共享服务字节，或整个版本字相等。其他型号字的差异及禁止覆盖规则保持检查。
- 损坏、机型错误、版本副本不一致、超大声明及修复 checksum 后的执行代码变更仍拒绝。
- 最终真实输入及版本兼容专项：28 passed、0 failed、0 skipped，包含两份实包、两机型合成版本的完整默认原生构建、纯数据导出及 HTTP 回读。
- 最终 `npm test`：502 项，428 passed、49 failed、25 skipped。对全部失败所在的 27 个测试文件，在干净 `b0c6c90` 工作树、相同输入及运行时条件下复测：119 项，70 passed、49 failed；失败名称集合完全相同，没有新增默认套件失败。既有失败包含目录/状态旧期望、边框构建断言及缺少 DOM 的界面测试；逐项名称保留在本地验证报告，不将全量写为通过。
- 真实新版完整原生 HTTP 验收：2 failed，均在预检期望 200 时收到原生 ABI 未适配的 400。测试已要求原始来源和组件版本保持，不再以“旧包提高版本”作为通过标准。这两个失败代表用户原始目标仍未完成，不能合并为基线已有失败。
