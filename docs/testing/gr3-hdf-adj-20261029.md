## 输入与根因

- 官方 GR III 2.10 RTOS：`builds/gr3-extension-validation/official-rtos.bin`。
- SHA-256：`8a4eafcad2716e0b21e9909264e1242e534f0e39e05cba82a53546ceb4070b67`，构建器保持原有精确哈希/preimage 门禁。
- 原厂 ADJ 21 记录构造、五槽赋值及 ID20 查表接线已有；故障是 `m10v_hdf_adj_available` 误解了记录 `+0x3c` 的返回契约。

## 变更与保护

仅将原生谓词由 `m10v_hdf_ui_owner()!=0` 改为 `==0`；保留既有导出名、记录 ABI、全部 82 个补丁、全部 20 个原厂记录、五个赋值列表和 ID20。构建器/独立 Node 校验器增加契约注释，避免再次按导出名误读。没有新增地址、补丁或 IIIx 映射点。

冷缓存不会影响图标资格；原厂进入路径调度 ID20 enter 后才由现有 bootstrap 读取 journal。图标循环与初始槽选择不增加文件读写。MENU 与 ADJ 的 owner/cache/journal、确认、取消、失败回读、错误提示和原厂退出均未改动。

## RED → GREEN 证据

修复前新增原厂 ARM 测试，明确复现三项错误：

1. 健康 owner、冷缓存下，期望 `(icon=874, visible=1)`，实际为 `(0,0)`。
2. 缺失 owner 时，期望全部隐藏，实际五个图标均为 874。
3. 原厂初始选择由前一个 Off 槽寻找 HDF，期望槽 0，实际留在槽 4。
