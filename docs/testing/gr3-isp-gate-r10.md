# r9 仍长时间处理：r10 定位包

用户这次提供的四份 MENU/IO 日志 CRC 全部有效，同一 build_id=4733158a，
对应 GR III r9；无拒绝页、冲突页。只保留环形窗口，不是完整执行轨迹。

## 本次日志能确认什么

MENU 保留序号2734至2797，反复出现私有效果入口0200f102的 factory phase2/3。
r9 只去掉了原厂入口轮询日志，私有入口也被频繁查询，因此仍产生同步 SD 日志负担。
r10 完全移除工厂查询内的日志，原厂和私有入口查询均不写诊断页。
回归测试要求重复工厂查询不产生日志；菜单实际构造、进入和操作仍有有限诊断。

IO 有38条记录，拍摄 recipe=5c000028 已走到 capture.owner.enter（event193），
但窗口内没有 JPEG 提交或等待返回记录。早期 trace 同时报告丢弃5条记录；
因此缺少 digital kind11 不能证明该阶段没有执行，也不能据此确定哪个 ISP 检查失败。
现有日志没有新效果快照中的计划、原厂工作区查询和完成标记，无法可靠区分这些条件。
没有证据支持通过删除等待、提前释放或改用 CPU 像素处理来修复。

## r10 增加的证据

在现有 JPEG 工作线程的文件系统安全入口，独立批量写出8条只读元数据（event198）：

| 标记 | 两个字段 |
| --- | --- |
| FX00 / 46583030 | 快照 magic、owner |
| FX01 / 46583031 | ready、sequence |
| FX02 / 46583032 | 漏光强度、模糊强度 |
| FX03 / 46583033 | planned、native_completed |
| FX04 / 46583034 | failed、source_si |
| FX05 / 46583035 | stock_workspace_bytes、stock_query_valid |
| FX06 / 46583036 | effective_grain_strength、grain_mode |
| FX07 / 46583037 | 当前 SI、原厂 SI+77c / SI+795 标记 |

这批记录独立于已溢出的前序 trace，不在 ISP 等待循环写卡，不读取或修改照片像素，
不改变计划、任务提交、完成、编码准入或资源释放判断。无 CPU 像素回退。
新增效果仍使用既有原厂 ISP 路径。r10 是进一步定位包，未声称真机故障已修复。
