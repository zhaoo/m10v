# M10V × GRemote 联动验收与日志

适用设备为 GR III 2.10 和 Android。先按《手机安装说明》安装同一包内的固件、SD 服务和 APK，再导入随包的新配对文件。保留既有胶卷库和设置。本包的修订记录与校验值见 `evidence/` 和 `SHA256SUMS`。

## 照片一键复用

1. 在机身选一卷 M10V 胶卷，将保存格式设为 RAW+JPEG。采用 GRemote 可写的拍摄参数，例如 M 档和固定 ISO。设色温 5600 K，分别拨动白平衡的两根偏移轴，设一组容易辨认的效果。关闭 Wi-Fi，只用机身快门拍一张。
2. 改变白平衡和曝光设置，拍至少三张连拍。换另一组明显不同的设置，再拍一轮。再切到另一卷，以便区分原拍设置和下载时的设置。
3. 用 Android 连接相机，在「照片 → 相机」分别保存每张 JPG 和 DNG，交错下载顺序。重新打开该照片，点「应用原拍配方」。为了独立核对两种文件，同一张的两种格式可分两轮单独下载验证，先验证只下载的格式，再下载其配对文件。等待应用完成及机身读回。记录原图文件名、复用后的胶卷、白平衡模式、两轴偏移、色温和当前模式可写的曝光值。
4. 用已安装的自定义胶卷重复第 1–3 步。用同一 ID、内容不同的胶卷做负例，确认提示安装拍摄时的胶卷版本，且原有机身设置保持。
5. 打开一张机身 DNG，分别用原拍和另一款受支持的胶卷在机内显影另存 JPG，检查回放。显影核对原厂 ISP 日志事件 `139`。

MCR2 由启用 M10V 胶卷的曝光产生。自定义胶卷须来自可验证的不可变存档。曝光复用依据当前模式下机身公布的可写项，物理曝光模式拨盘和 Auto ISO 意图需要在机身核对。旧照片没有完整快照时仅在确有拍摄时手机记录的情况下提供该记录。

## U 档与 ADJ

1. 各设三组不同胶卷、白平衡和效果，用机身原有「保存设置」存到三个设置箱，再用机身原有设置分配给 U1、U2、U3。
2. 保持 Wi-Fi 关闭，在 U1、U2、U3、普通档之间切换两轮，再关机重启复查。每档分别拍一张并核对对应原拍快照。日志 `145` 对应扩展保存，`146` 对应加载。检查 `failed` 及胶卷存档代次。
3. 在 ADJ「影像控制」用拨轮移动高亮，观察取景颜色变化。取消后应恢复原来的取景，拍摄的胶卷保持原选择。再次预览并确认，核对取景及下一张照片使用新胶卷。日志 `144` 对应确认。预览覆盖胶卷颜色，颗粒、漏光和 HDF 等成片效果在拍完后核对。
4. 在机身「设置 → 关机图」选择三张内置图片中的任一张，关机检查显示并重启复查，再完成一次撕纸叠映，检查轮廓原图、合成图和日志。

## 收集日志

- 测试后正常关机，从卡根目录拷贝存在的 `M10VCP0/1.BIN`、`M10VIO0/1.BIN`、`M10VAK0/1.BIN`、`M10VTO0/1.BIN`、`M10VMN0/1.BIN`。每组用文件名中的实际数字。尽快拷贝，日志为循环页。
- 解压包后，可用 Python 3 解码已拷贝的卡日志。将下面的通配符路径改为本地日志目录。

  ```sh
  python3 tools/read_gr3_debug_log.py ./sd-logs/M10V*.BIN > camera.json
  adb logcat -d -s GRemotePhotoTransfer > gremote-transfer.txt
  ```

- App 首页右上角可复制「诊断信息」。回传日志时附拍摄顺序、原图文件名和异常步骤。保留配对文件在本地。

## 验证范围

最终固件回读核验 339 处钩子。ARM 测试运行原厂拍摄及 JPEG 入口、相邻曝光的乱序 MakerNote 写入、JPG/DNG 标签构造、纯 ISP 路径、原生拨盘入口及 ADJ 取消和确认站点。主机侧测试覆盖 MakerNote 解析、白平衡和胶卷身份、配方应用读回及撤销。相机驱动、文件写入和 Android 连接分别通过模拟边界验证。GR III 实体机的快门连拍、显示、写卡、兼容性和耗时需执行上述用例。iOS 此轮没有测试包。
