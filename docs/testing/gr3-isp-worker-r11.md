## r11 改动

只扩充诊断，不删除任何完成/归属/工作区检查，不伪造成功，不改变任务释放。
新增效果仍走原厂 ISP，无 CPU 像素处理、CPU 噪声生成或软件回退。

1. 已证明的 generic receiver 安全重接点：原厂 handler 返回、引用计数锁释放后，
   owner callback 回收 recipe 之前，对开启效果的 kind19/4/12/10/11/5 分批保存现有 RAM trace。
   FXM（46584d00）记录 kind、request+24、digital context+48/+49。
   任务生产者和处理回调仍仅记录 RAM，不写卡。
2. 原厂设置完成、工作区查询返回、原厂执行返回、效果完成各记录一次 FXH 检查点。
   只在开启效果时启用，不在像素循环、IRQ、ISP 等待循环中写卡。
3. 永久保护等待前记录一次具体失败原因和本张快照，日志失败不影响控制判断。
   FXH 值1=设置完成、2=工作区查询返回、3=原厂执行返回、4=效果完成；
   10=执行参数、11=原厂结果/查询、12=工作区、13=模糊参数、14=部分完成、
   15=纹理渲染返回失败、16=完成发布失败；20..24分别为编码context/tone/快照/参数/完成检查。

仍不能把永久等待当成可交付的正常失败策略。当前保留它是为了避免在 DMA 状态未知时释放活跃缓冲。
后续须根据实际失败点修正正常调度；若要走原厂取消/失败完成，也须证明其资源生命周期。
这版不是根因修复包，不声称已解决相册卡住。
