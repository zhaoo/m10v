## 新证据与最小修正

R1 只在 BaseController 的原始电源包入口记录关闭状态。官方 `532231e4` 可以直接把 MAIN 转发给 `53221a1c`，绕过该入口。用 R1 最终 BIN 重放这条原厂指令链：原始 MAIN → 原厂 ADJ 映射 → 0x35 → 原厂关闭处理 → 0xb8 → 原厂影像控制退出 → 返回取景，仍触发了自定义菜单工厂。R1 的测试只模拟原始 BaseController 分发，漏掉了这条分支。

R2 在逻辑 MAIN 入口同样记录关闭状态，仍限定 ADJ 路由，保留原厂事件和返回值。对同一条真实原厂链重放，R2 没有菜单工厂或存档调用，影像控制退出回调仍正常清除原厂状态。

第二处是 A/B 正常退出：LiveView enter 无条件重新创建/查找菜单所有者、迁移和读取存档；A/B 已启用时还再次从 SD 校验配对。历史实现原本有“预览缓存已就绪则不重载”的门禁，十槽迁移时变成了每次重载。R2 将成功迁移/加载记录在本次 owner 的 RAM 状态内；退出复用已发布缓存，配对验证也读缓存。首次初始化失败可重试；新 owner 构造清零；菜单写入继续发布新缓存。旧存档迁移、十槽、原厂预设和已有胶卷功能均保留。

没有更改原厂 UI 的列表恢复、资源、关闭调度或成像算法。R1 的名称映射保留，用户该项反馈只适用于名称；不扩大为整包验收。

以上证明 R1 漏掉的调用路径及 R2 对这些调用的修正，**不等于已证明物理机身卡死消失**。物理关机和 A/B 退出仍须用户实测。
