r7 实测可使用印花功能，但轮廓偏糊，深色背景也呈白色。r7 的亮度门控会显著削弱高光色度，暗底纯白说明高光门控无法解释全部现象。精确到芯片算术节点的掉色位置仍待相机确认。

r8 借用已有实机反馈的漏光路径。每款使用两张零背景 UV 权重纹理，分别进行正向和负向混合，两趟使用原生 identity 权重表。第二张纹理提供亮度遮罩，提白端点收至剩余亮度的 75%。r8 优先保留图案色度，亮背景上的彩色可能更明显。操作依次为两次原生缩放、两次色度混合和一次亮度混合，合计仍为五个 ISP 任务，复用一个工作区。CPU 负责参数和任务同步。

七款原稿重新栅格化到 768×512，去掉软化滤镜。原生纹理从 320×224 增至 512×304，采样点约为 r7 的 2.17 倍。14 张纹理共 3,268,608 字节，位于 `[0x54cd0000,0x54fee000)`，SHA-256 为 `adfc792bdf010de0bebde30168b33aed6d228143fbe5f6e8bb8bbf3d1b72936a`。旧纹理的字节及散列保持一致，基址移至 0x54220000。编译和独立回读检查成对纹理的指针、极性、大小、哈希及代码边界。

保留 MENU → 设置 → 效果 → 胶卷印花、现有七款、传感器坐标布局、已有设置日志和逐张快照。包内 `SD/M10V/FILMS.M10` 对应现有胶卷目录。只在需要更新胶卷资源时合并该文件。通过原有更新流程安装对应机型 BIN，并保留同机型 r7 或上一个已验证的恢复包。

实拍先关掉漏光、颗粒、模糊和 HDF，用同样的曝光及白平衡，给「宝可梦」或「绚烂彩虹」分别拍一张深灰和亮灰背景。对照 JPEG 放大图案边缘，检查深底是否显色、亮底是否仍自然。再对照关闭印花，拍三张连拍并检查即时回放。其他五款的图案和方向也可在同一场景对照。

离线模型在中性 Y=24 和 Y=220 两种背景上均有明显色差。两机型通过同源导出和独立 BIN 回读。124 项 Python 和 ARM 回归、1 项 LUT 检查以及最终 GR III BIN 上运行的 5 项回归通过。完整 Node 套件有 555 项通过、64 项失败、42 项跳过。64 项失败均可在上述 main 基线复现。具体执行结果见包内 `evidence/final-validation.log`。
