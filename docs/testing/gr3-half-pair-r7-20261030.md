## 已实现路径与打包门禁

每张曝光分别使用本机原生 ISP 处理；两帧的保存和拼接改用有明确所有权及原生完成回执的 IIP 空间处理。不得跨曝光保留借用的原厂图像指针，不得在首帧所属银行清理后继续引用其像素。

构建器与打包器已加入以下强制门禁。`manifest.half_pair` 与 `receipt.composition.half_pair` 必须一致声明：

- `backend: "native-IIP"`；
- `frame_filesystem_calls: 0`；
- `cpu_pixel_reads: 0`、`cpu_pixel_writes: 0`；
- `first_original_preserved: true`；
- `camera_tested: false`，并提供范围内且实际安装的编码前 ARM 调用。

旧文件暂存路径和缺少这些字段的 r6 回执必须拒绝，不能仅改包名。诊断日志和原本的照片保存仍会写 SD；上述零图像文件调用仅指双拼的帧暂存与合成，不意味着相机完全不执行文件操作。

首帧通过原生 Transfer 复制至单独分配的私有内存；第二帧也先复制至另一个私有分配，再以串行原生 Fill → 两次 Transfer → 两次 Resize 完成双拼和两级预览。每步等待精确完成回调返回后才发布描述符或释放内存。CPU 只操作标量状态与描述符；整帧 CRC、行文件读写与 CPU 像素拼接不链接到固件。两张之间的自动回看保留首帧，显式切换其他比例、方向或尺寸变化和所有者析构会取消或重新开始。

r6 日志同一组出现两次 first-ready，没有 pair-composed；旧日志不足以唯一定位首帧重置来源。r7 移除了文件暂存路径，并新增事件 221（owner/generation/私有 token/状态）和 222（原生 Transfer/合成及缩略图阶段的时钟差），供实机确认状态与性能。日志元数据仍写 SD，不能将双拼的零帧文件操作描述为整台相机零文件操作。
