## Approaches

1. 原厂颗粒 + ISP 合成：最接近当前集成路径，但使用整帧 ARM/NEON RNG；用户已拒绝。
2. CPU 纹理与模糊：实现容易，但违反本次约束；排除。
3. **拟采用：构建期纹理 + 原厂 ISP Loader/LUT/Blend/SPF。**
   CPU 仅提交元数据。需要验证纹理寻址、硬件数学、空间核和任务所有权；
   在证据完整前不以菜单选项宣称支持。

第三条及以下实现方案已获用户确认；硬件能力与性能仍须由后续证据证明。

沿用机内「效果」入口、现有 HDF 与边框交互；新增三个独立子菜单。

首版仅覆盖保存 JPEG 及其内嵌预览；空间效果不承诺实时取景，禁止 CPU 取景兜底。
RAW 像素不受新增效果修改。现有胶卷色彩取景行为保持。

| 效果 | 首版参数 | 目标行为 |
| --- | --- | --- |
| 漏光 | 强度 关闭/弱/中/强；位置 左/右/双侧；范围 窄/中/宽 | 暖红橙边缘入光，柔和过渡，保留高光层次 |

现有不支持颗粒的特殊渲染器继续受门禁保护，完成独立组合验证前不扩展支持范围。
菜单参数的最终档位取决于可验证的硬件表达与样张，不能提前承诺任意连续半径或彩色颗粒。

## 成像路径

### 颗粒

电脑生成多尺度、零均值、具有密度相关性的颗粒资源；保留生成器版本与资源哈希。
在相机上使用 ISP 读取纹理、曲线调整与图像混合。每张选择资源/偏移/相位只更改元数据。
必须验证周期性、条纹、固定图案、尺寸与亮度相关性，不能以静态重复噪点冒充真实胶卷质感。

首先验证 Loader 的重复/ROI 能力及 DMA 地址域。若不能直接重复小纹理，评估
硬件搬运生成工作面及图节点数量。不能改为 CPU 扩展，也不能假定完整 24MB
资源塞入固件就安全：容器上限、MMU、启动内存和 DMA 可达性是不同约束。
若小纹理无法由硬件重复/搬运，或节点、工作区和时延超过实机对照要求，
该路线保持不可启用，继续研究其他原生图，不以减少检查或 CPU 填面解围。

### 漏光

构建期生成平滑遮罩，ISP 调整强度并进行暖色混合。验证实际 Y/CbCr 域、范围、
色度采样与高光保护。边缘遮罩跟随保存方向，不因横竖拍或 EXIF 旋转落在错误位置。
先验证 Loader → LUT/GPC → Blend → Store 的最小图，之后再开放位置和范围。

### 模糊

从原厂 SPF/Clarity 空间阶段研究可验证的低通响应；若频段控制足够表达目标，
复用原厂金字塔，否则使用已解码的 SPF 核。先验证脉冲、细线、边缘及均匀场。
不能直接把 HDF 改名，也不能覆盖 HDF 的强度字段。组合时须明确系数合成或独立阶段的
工作区与顺序，并确认不会重复模糊。

### 生命周期与兼容

所有参数在真实拍摄任务入口逐张冻结，规划和执行使用同一份快照。
使用现有 owner 缓存，拍摄入口不做文件读取、分配或阻塞。
新增版本化效果记录，不回收旧胶卷状态的废弃字段；缺失/损坏记录按关闭/沿用规则处理。
保留现有胶卷目录、十槽、SD 自定义卷、HDF、边框、光晕、水印、RAW 边界和存档迁移。

新图必须有资源预留、原厂调度/互斥、真实完成校验及失败后的 DMA 静止证据。
只由真实成功的硬件执行产生完成标志；失败不能切到 CPU 或伪报成功。
已经提交 DMA 后不能因超时就释放仍可能被硬件使用的内存。

建议的组合顺序为现有胶卷色彩 → 漏光 → 模糊/HDF → 颗粒 → 边框/水印；
最终顺序需结合现有光晕与原厂空间阶段拓扑验证，并以样张确认。
新增三种效果只作用于照片区域，不污染边框、文字或缩略图 padding。
不能为满足该顺序重复执行既有色彩、光晕或 HDF；不支持的组合在构建/菜单中明确拒绝。

## 分步实现与验收门槛

1. 对两个机型建立 Loader 纹理寻址、Blend 数学、SPF 核与任务 owner 的独立契约。
2. 各效果先做最小 ISP 图，离线执行原厂控制流；像素保持未映射，任何 CPU 像素访问立即失败。
3. 证明规划容量、实际提交、等待、释放与失败路径，再接入逐张快照和完成交接。
4. 接入菜单、保存、网页构建参数和机型门禁；默认关闭，旧配置行为明确迁移。
5. 针对原厂、胶卷、自定义卷、首张、排队、多种画幅/方向、HDF/边框/水印组合验证。
6. 沿现有导出链构建 GR III / IIIx 可识别测试包，提供产物身份和恢复说明。
7. 真机对照原厂正片/负片，检查即时回放、相册、至少连续三张及纹理视觉质量。
   没有实测不承诺帧率、存片秒数或真实胶卷匹配。
