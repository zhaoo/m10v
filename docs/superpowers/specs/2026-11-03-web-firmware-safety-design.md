# 网页固件严格校验与排队

用户于 2026-11-03 明确选择：服务端生成前核验来源、机身声明与配置；生成后完整重建并逐字节比较；浏览器下载前 SHA-256 校验；失败拦截。随后明确选择一并接入任务队列、排队进度与取消，先保持单任务运行。

采用服务端有界异步任务队列，单个任务覆盖生成和重建验证，避免生成器的全局 building 标志在两阶段间被其他请求抢占。网页提交后轮询任务状态，拿到 ready 后才请求下载。队列/结果内存/有效期有上限；取消排队任务不启动，取消运行任务等待清理完成后才启动下一项。历史同步 API 也通过同一队列和相同校验，不形成旁路。

生成前对精确官方 GR III 2.10 / IIIx 1.60、对应机型版本、明确来源和预检配置绑定。周年固件、第三方/未知机身来源、抬版本继续拒绝。机身已装 M10V 时要求保留实测包 SHA 记录，但明确只是人的声明。仅配置预检可以先执行，真正生成时必须具备机身声明。

生成完成后从当前源码按同配置重新构建，最终 BIN 包含开关机图片等所有变更，必须逐字节相同，再核对完整解码、版本副本、来源、回执与长度。校验记录只允许由服务端校验器签发，统一下载出口再核对实际字节。浏览器拿到实际 Blob 后计算 SHA-256，绑定来源/配置/文件名/长度/服务端校验记录；完成页再次下载也重验。修改方案/来源或取消后不允许旧任务发起下载。

`download_allowed` 仅代表电脑端检查通过，`installation_allowed=false`、`camera_tested=false` 始终保留；不把下载许可解释成相机安全认证。官方备份核对原包与 ZIP 内原件，不受自定义运行体重建要求影响。原生代码和生成器保持不变，两个支持基线的固件字节应保持一致。

前端本地编译需要迁移 Python/LLVM/ARM 验证链，不在本轮替换。默认并发保持 1，完成资源实测后才能提高。二阶降级另做离线研究，没有硬件恢复测试条件，不能标记稳定或开放网页入口。完成本地实现与网页检查后交付可审查结果；本轮没有合并、推送或生产部署授权。
