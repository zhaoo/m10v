## 方案选择

1. **向外扩展画布（已选）**：完整保留裁切画面，新增边框区域；需要核实原厂编码、缓冲及回放对扩展尺寸的支持。
2. 保持成片尺寸、等比缩小画面：可限制画布内存，但降低有效画面分辨率；本期不采用。
3. 保持尺寸、直接覆盖边缘：实现较简单，但损失构图；本期不采用。

硬件实施优先核查原厂 Loader / Store 的目标矩形及常量填充能力，必要时核查 Blend 的坐标遮罩合成。当前仅有原厂 IIP 原语证据，没有已验证的边框执行图。禁止用已有 ISP 色彩完成标志代表边框完成，也不从合成类名称推断硬件支持。

## 一期默认提案

以下是实现建议，尚不是用户已确认的外观细节：

- 菜单：效果 → 边框 → 关闭 / 拍立得 / 胶卷；全局独立设置，默认关闭，确认保存、取消恢复，重启保留。
- 拍立得：白色边框，左右和顶部等宽，底部约为其三倍。普通边宽按裁切后短边的 4% 计算。
- 胶卷：黑色外框，两条相对边排列浅色齿孔；框宽按短边的 6% 计算。齿孔完全位于新增区域，不侵入照片；一期不加入品牌、随机编号或文字。
- 边宽和孔位按硬件平面/色度/编码对齐取整，误差限于对齐需要；不得拉伸照片。横竖画面依拍摄方向布置边框，回放方向一致。
- 一期不增加用户可调边宽、颜色或额外存储模式。

## 几何与组合契约

先执行现有画幅与焦距裁切，再用本张真实有效宽高生成边框布局。内图尺寸不变，按各边宽度定位；拍立得仅水平居中，底部保留加宽区域。不能硬编码 6000×4000，也不能再次按 3:2 计算 XPan 或 6×7。覆盖 3:2、1:1、4:3、XPan、6×7、各画质大小和两机型焦距裁切。

扩展画布必须核实原厂支持的尺寸、stride、对齐、工作内存与 JPEG 限制；现有代码中的 8192 检查不是硬件能力证明。若原尺寸外加边框超出限制，视为待解决阻塞，不静默裁图或降分辨率。

具体风险：以 6000×4000、普通白边 160、底边 480 为例，外框为 6320×4640（实际另作对齐）。当前 `m10v_library_capture.c` 的 `thumb_load` 接受宽不超过 6144、高不超过 4096；必须核查全部消费者、原厂调用及分配规划，不能只放宽这两个数值。这个软件检查不证明原厂硬件上限。

边框位于胶卷色彩及图像空间效果之后，避免白框被胶卷染色。既有日期、胶卷名水印仍以原画面矩形定位，保留其颜色与角落语义；边框不默认把水印移到白边。已有水印等明确启用的 CPU 残余处理不构成本功能新增 CPU 绘框的许可。

RAW 像素及原有裁切元数据语义保持不变；JPEG 主图、独立预览、缩略图和即时回放必须使用一致的带框几何，不能只改最终 JPEG。另建议一期提供实时取景边框提示，此项仍待随设计确认；提示可走显示叠加层，不得改变 AF 坐标或原来的取景裁切，也不作为 ISP 成片合成已完成的证据。

## 性能、生命周期与失败边界

ARM CPU 仅允许有界的布局、硬件参数、少量模板准备与任务管理；本功能不得引入整图 CPU 填色、复制、缩放或逐像素遮罩生成。若齿孔需要整幅 CPU 遮罩，必须继续寻找硬件/小模板复用能力，不能以软件方案交付。

边框设置在真实任务投递前随本张状态冻结，排队照片不受后续菜单切换影响。硬件任务使用原厂调度和资源所有权，完成校验绑定本张 recipe、几何和设置；源缓冲不得越界或释放后访问。不得在快门任务入口读文件、分配或等待。

默认关闭时不新增图像访问、工作面申请或硬件合成。开启时必须记录新增输出缓冲及模板的容量、峰值和释放时机，不假定硬件执行意味着零内存或零延迟。

不提供 CPU 绘框回退。硬件错误不能伪报已加边框、损坏原图或留下半成品；具体恢复应沿已核实的原厂失败路径保全照片，并产生可见错误。未能安全闭合前禁止启用成片功能。

## 两机型交付与验收

共享菜单、设置、布局与合成策略，沿现有严格差分移植分别构建 GR III 2.10 / GR IIIx 1.60；每次检查官方身份、受保护机型字、补丁 preimage 与最终封包回读。不直接共用 BIN。

离线验证包括：存档迁移、关闭/确认/取消、排队快照、全部画幅与横竖几何、对齐/溢出、硬件执行完成与拒绝路径、RAW/别名/释放保护、无 CPU 整图处理、主图/预览几何一致、最终两款产物身份和空间预算。

实机分别验收两机型的菜单、全画幅首张、连续至少三张、RAW+JPEG、即时回放、相册、旋转和重启。相同场景、画质、卡与效果配置对比关闭边框及原厂正/负片；记录拍摄恢复、回放可用时间和连拍稳定性。没有实测数据不保证速度。
