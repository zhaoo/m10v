## 新旧固件差异

两个机型的新旧差异具有相同结构：

| 项目 | 2.10 / 1.60 | 2.20 / 1.70 |
| --- | --- | --- |
| 展开总长 | 59,718,388 | 59,798,532 |
| RTOS 载荷 | 17,520,064 | 17,520,384（+320） |
| RES 载荷 | 6,595,272 | 6,675,096（+79,824） |
| 初始化复制源 | `0x5407b540` | `0x5407b640` |
| 初始化复制目的 | `0x55000000` | 相同 |
| 初始化复制长度 | `0x3a080` | `0x3a0c0`（+64） |
| BSS 起点 | `0x5503a100` | 相同 |
| BSS 终点 | `0x55804374` | `0x55803c34` |

分区逐字节比较：BOOTPARA、DRAMPARA、PARTPARA、M0、BOOT、LINUX、INITFS、ICONBIN、FDRVPARA 相同；RTOS、SRIC、CPU、SHELLCMD、RES 发生变化。每个机型 CPU 仅 28 字节不同：`0x7c` 校验、`0x91..93` 版本、`0x12b..13e` 不透明 20 字节区，以及 `0x5135` 一字节。未独立证明这 20 字节区的语义，不能将它当作新的安全签名或恶意标记。

地址变化不是统一偏移。已有目标描述的示例是 `0x5313d850→0x5313d8e0`、`0x5351ea9c→0x5351eb8c`、`0x536dd3e0→0x536dd3b8`、`0x53b3488c→0x53b341b4`。照搬旧版菜单/函数地址或整体加一个偏移可能破坏启动；修正加和不会修复地址错误。

不能把同偏移下约 1,389 万个 RTOS 差异字节解释为同等数量的语义改动：代码/资源移位会扩大该数字。两个新机型的 RTOS 相差 27 字节，旧机型相差 31 字节；这些近似也不授权跨机型互刷。

机器可读完整分区和启动证据：本地忽略目录 `builds/firmware-safety-audit-20261103/official-comparison.json`、`cpu-changes.json`。

## 能否降级后再刷

2.20 中实际原厂更新器的 ARM 局部执行再次确认：以当前组件 2.20.20.28 为条件，旧 2.10 包在所测类型中被拒。说明正常更新器有版本门禁；这属于既有版本比较行为，不能直接解释成新“下毒”。同一测试还模拟了历史抬版本/允许恢复的桥接机制，3 项通过，但没有执行真实 Flash 写入或完整启动。

首次安装执行的是机身现存更新器，待刷包里的补丁不能提前修改它。抬高包版本再装旧运行体并不等于官方降级；即便突破比较，也不能证明 CPU/RTOS/持久化配置兼容或一定可恢复。因此对官方 2.20 / 1.70、未知作者固件和高内部服务版本，当前没有可以推荐为安全的降级后刷入路线。普通用户应停止，不能改四处版本号、改文件名或试旧桥接包。

2.10 / 1.60 的同版本刷入，与跨公开版本降级不同；公共菜单版本不足以识别四段组件版本或第三方运行体。第三方或未知来源的同版本机身也不能直接放行。

## 新增的刷前检测

入口 `scripts/check_gr3_flash_safety.mjs`；实现 `node/gr3-flash-safety.mjs`。按用户已确认范围：

1. 先核对两个支持来源完整 SHA，再进入任何生成器；拒绝周年、未知及修改过的来源。
2. 核对声明的机型/版本/来源；第三方或未知来源拒绝。经验证 M10V 要保留此前实测包 SHA，仍明确只是声明，不读取相机。
3. 核对候选的独立下载摘要和回执，严格解码机型、分区、CPU/容器加和及组件版本，拒绝抬版本伪装。
4. 根据回执配置重新运行已存在的生成链，检查源码/配置指纹并要求整包逐字节相同；修复加和和伪造回执不能代替源码重建。需要候选对应的源码/工具链，失败即停止。
5. 即使一致，仍输出 `offline_verified_camera_unverified`、`installation_allowed=false`、`camera_tested=false`，退出码 2。错误/不支持退出码 1。不提供自动准许刷机的码。

输入文件只读；使用临时编译目录/缓存，不导出新 BIN，不写卡，不控制相机。没有完整回执的历史网页下载、其他作者固件或机内持久化状态，无法凭一个 BIN 自动证明安全。SHA 和回执都不是数字签名；核查工具和源码本身必须来自已审查的 checkout。

使用示例及边界见 `skills/m10v-firmware-safety/references/firmware-safety.md` 中“本地候选的保守刷前检查”。该工具没有替代网页下载接口或改变旧固件产物。

## 菜单/设置差异应该如何处理

文件版本相同不代表函数地址、私有 tone ID、结构体或存档 ABI 一样。M10V 有自身 magic/version/长度/CRC、M10V6 A/B 存档及已知旧版迁移；它们不能验证其他作者对原厂机内设置的所有修改。直接把新 patch 叠到第三方 BIN 被完整来源 SHA 拒绝，但“机身以前安装过第三方固件”的持久化遗留不在文件检查范围内。

不能未经证据就认定菜单配置造成此次故障，也不把“恢复出厂/删除设置文件”当作已验证通用修复。保留用户设置和照片，不自动清理、格式化或迁移。当前保守规则是未知来源停止，待取得具体固件及可靠机身证据后再做专门迁移研究。
